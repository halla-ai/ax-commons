# Contribution boundary

`core.mjs` is dependency-free and browser-compatible. It accepts only user-selected contribution objects. It never reads conversation logs, and preview and approval perform no network calls. `createContributionFlow` holds preview content only in memory; exported status records contain consent and repository receipts without contribution text. Persistent applications must store those receipts before transmission and retain uncertain outcomes for reconciliation.

The browser submits `{candidate, hash, approved: true, scope: "public", expiresAt}` only after local preview and a separate explicit click. The receiver must independently call `preparePreview`, validate consent against its returned hash, rate-limit, consume single-use receipt IDs and persist metadata before calling the repository adapter. `reviewers-only` is unavailable until a genuinely private intake exists. The release copies the single `core.mjs` source to `/contribute/core.mjs`.

`createGithubTransport` is restricted to `halla-ai/ax-commons` and the HTTPS GitHub API; redirects are rejected. Use a repository-scoped credential with contents and pull-request permissions. Contributions create a branch and a review PR, never bypassing human review. Each contribution path is unique; replacement of existing content is rejected.

Withdrawal closes an unmerged contribution PR and removes its source branch. Published content creates a removal PR; status remains `withdrawal-pending` until a fresh repository readback confirms the current file is absent. A changed current file requires operator reconciliation. The deployment scheduler must run expiry sweeps and operators must review and merge removal PRs promptly. `sweepExpired` is provided for local adapters; the receiver uses its persistent receipt store and scheduled handler. Existing copies and immutable Git history are not erased, and CC BY 4.0 is irrevocable for copies already published.

The scanner blocks known email, phone, national ID, card, credential, injection and remote-execution patterns. It is a conservative pre-send gate, not proof that arbitrary content contains no personal data or malicious instructions; domain and security reviewers remain required. CI checks changed tracked contribution content, while skill metadata validation runs separately. Safe contribution JSON requires type, slug, purpose, sources, reviewer, version, sunset, issuePath, content and a pseudonymous contributor handle. Failure cases and issue reports are included in generated recognition.
