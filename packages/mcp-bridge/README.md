# MCP remote bridge

`registerRemoteTools(server, ledger, options)` registers `submit_contribution`, `sync_metrics` and `revoke` on an official MCP SDK `McpServer`. The returned `consentStatus()` adds safe remote configuration, consent receipt and transmission state to the local server's existing consent tool.

- Operator options: `endpoint` (HTTPS origin without path, credentials, query, fragment or custom port), `metricsToken`, `contributionToken`, and pseudonymous `programId` (32-64 lowercase hex characters). Credentials must be issued tokens of exactly 64 lowercase hex characters. Missing or malformed configuration keeps remote uploads unavailable. Tool arguments cannot replace the configured endpoint.
- Contribution preview takes one explicit candidate supported by `packages/contributions/core.mjs`. Preview text and candidate stay in process memory, expire after 15 minutes, and are limited to 20 previews. Submission requires the preview ID, exact SHA-256 hash, `approved: true`, `scope: public`, and a future expiry within 90 days. It consumes the preview before HTTP, including failed requests. A UUID and withdrawal key are generated and persisted locally before POST. Lost responses retain the safe ID with `publication-uncertain`; use `action: status` or `revoke` to reconcile it before preparing another contribution. The withdrawal key is sent only in the dedicated request header and is never returned in tool output.
- Metrics requires explicit approval per calendar UTC month. It sends replacement snapshots of enum task/review/reuse/skill cells with counts at least five. Older ledgers without skill tags use `skill_id: null`. The local contribution count is also suppressed below five. Source/device identity, task timestamps, minutes and conversation content never enter the payload.
- Revocation disables the local metrics period before requesting removal, waits for an active upload, and prevents later uploads for that period. Contribution revocation uses the locally retained receipt credential. A removal PR remains `withdrawal-pending`; only a confirmed server receipt can report `withdrawn`. Existing copies and immutable history/releases can remain.
- No scheduled network activity occurs. Expired contribution receipts appear as `expired-withdrawal-pending` until the user invokes withdrawal. The hosted expiry process is separate.
- SQLite bridge records contain only receipt metadata and a local revocation credential. The credential is omitted from consent output and must be excluded from JSON ledger exports. Deleting the local ledger removes the revocation credential; keep it until remote withdrawal is complete. Each operation opens the current ledger file and closes the connection so P1 deletion/recreation does not leave a stale handle.
- HTTPS requests reject redirects, time out after 15 seconds and read at most 8 KB of response data. Errors never echo server-controlled content. A successful remote mutation followed by a lost or malformed receipt remains uncertain, with its locally retained withdrawal control. Publisher updates preserve a pending withdrawal written by another client sharing the ledger.

Run the focused tests with `node --test --test-concurrency=2 packages/mcp-bridge/test/bridge.test.mjs` from the repository root. They use a fake transport, real temporary P1 ledger and an official MCP SDK in-memory client/server validation check; no live user or remote service interaction is required.
